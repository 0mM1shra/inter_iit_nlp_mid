\subsubsection*{\color{primary} 1. Problem Domain Insights \& Key Challenges}
Traditional enterprise CRM platforms rely on passive dashboards requiring manual account manager monitoring. Transitioning to an \textbf{Ambient Agentic Customer 360 Desk} introduces three core domain challenges:
\begin{itemize}
    \item \textbf{Ambient Execution vs. Prompt-Based Chatbots:} System must operate as an asynchronous background engine, continuously triggered by multi-modal event streams or scheduled account checks rather than waiting for human prompts.
    \item \textbf{Early Lead Time vs. Premature Overreaction:} The system must infer subtle behavioral shifts early (e.g., identifying pre-churn savings withdrawal) while suppressing premature, low-confidence interventions on noise.
    \item \textbf{Red Herring Isolation:} Real-world financial telemetry contains high-variance noise (e.g., tuition transfers, vacation refunds, tax deposits). The system must correlate multi-domain signals over time to isolate real signals.
\end{itemize}

\subsubsection*{\color{primary} 2. Dataset \& Event Stream Learnings}
Deep analysis of the multi-source event stream package and practice scenario timelines yielded key structural insights:
\begin{itemize}
    \item \textbf{Multi-Source Schema Envelope:} Payload ingestion normalizes streams across \texttt{card\_payments}, \texttt{ach\_wire}, \texttt{core\_banking\_ledger}, \texttt{trading\_brokerage}, \texttt{loan\_kyc}, \texttt{web\_app\_events}, and \texttt{support\_logs}.
    \item \textbf{Out-of-Order Watermarking:} Ingested events are replayed via an event-time watermark queue (\texttt{event\_time} vs. \texttt{ingestion\_time}) to prevent late-arriving packets from corrupting 30-day windowed rolling rollups.
    \item \textbf{Cross-Domain Signal Correlation:} Evaluated ground-truth timelines (\textit{Medical Hardship}, \textit{New Child Event}, \textit{Churn Risk}) confirm that high-confidence state inference requires correlating signals across KYC updates, transaction anomalies, and support ticket sentiment.
\end{itemize}

\subsubsection*{\color{primary} 3. Current Architectural Progress Achieved}
\begin{itemize}
    \item \textbf{Per-Customer Shared State Board:} Designed a structured blackboard scoped per customer ID. Swarm agents (\texttt{UsageAgent}, \texttt{SupportAgent}, \texttt{TxnAgent}, \texttt{KYCAgent}) write structured conclusions to eliminate multi-tenant memory leakage.
    \item \textbf{3-Tiered Memory Architecture:} Formulated Working Memory (session context), Episodic Memory (decay-weighted historical event RAG), and Semantic Memory (product/policy RAG).
    \item \textbf{Multi-Agent Debate \& Refiner Topologies:} Implemented debate protocols for reconciling contradictory swarm reads (e.g., tax deposit vs. app drop) and a Critique-Refiner pass for tone/compliance checking.
    \item \textbf{Safety Rails \& Calibrated HITL:} Integrated hardcoded regex guardrails for instant legal/AML threat bypass, data-layer PII redaction, and citation-backed human-in-the-loop (HITL) checkpoints.
    \item \textbf{Automated Evaluation Harness:} Built a Python scoring harness (\texttt{evaluate\_scenarios.py}) measuring inference accuracy, action precision, HITL calibration, and false-positive avoidance against ground-truth benchmarks.
\end{itemize}
